# Supply Chain & Stockout Risk Intelligence Platform

MATH 461 educational FMCG prototype. A warehouse inventory manager reviews SKU-location risks for the next seven days. Data is entirely synthetic; no actual Multan company data, measured savings or deployment readiness is claimed.

## Run

```bash
python -m pip install -r requirements.txt
python generate_data.py
python feature_engineering.py
python model.py
python compare_models.py
streamlit run app.py
```

Run from the repository root. Generator paths are relative to its own file. Generation overwrites the six synthetic source CSVs; rerun all downstream commands afterward. A fixed seed and fictional labels remove the generator's Faker dependency. Warehouse names are generic, not real company locations. Open EDA.ipynb for exploratory plots.

## What is implemented

- One observation: SKU × warehouse × end-of-day snapshot.
- Target: any zero-stock end-of-day snapshot in days 1–7 ahead. This inventory-depletion proxy is not identical to proven unmet customer demand.
- Initial Decision Tree, interpretable rules, chronological train/validation/test, full horizon gaps and validation-only threshold selection.
- Separate baseline/model comparison: training-only preprocessing and three expanding temporal folds, Logistic Regression, Decision Trees and Random Forest.
- Existing Streamlit review queue and separate what-if simulator. The simulator does not alter the fitted model.

The dashboard uses stockout_model.joblib generated by model.py. comparison_selected_model.joblib is a separate experimental pipeline; it is not silently wired into the dashboard. Class-weighted scores need calibration before interpreting them as reliable probabilities.

## Current measured results

Revised dashboard Decision Tree: precision 0.251, recall 0.785, F1 0.380. The separately selected Logistic Regression has test precision 0.435, recall 0.506 and F1 0.468. It was selected on validation average precision, not test performance. See RESULTS.md for workload and baseline tradeoffs. Different training protocols mean those two figures are not a controlled algorithm comparison.

## Action and limits

High: manager reviews stock and open POs today. Medium: monitor and review tomorrow. Low: routine monitoring. The software does not automatically order or optimize quantities. Demand forecasting, PCA/clustering, calibration and measured business impact are future extensions. Real data, unit/timing checks, staff evaluation and an independent future test period are required for business use.
